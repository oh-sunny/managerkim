# 공지 초안 톤 가이드

당근의 공개 공지 12개와 FAQ 18개를 참고해 사내 행사·복리후생 공지에 적용할 작성 기준을 정리했다. 당근의 공식 브랜드 가이드는 아니며, 아래 기준은 수집 자료에 대한 관찰과 이 프로젝트의 작성 제안이다.

## 레퍼런스 사용

- 같은 폴더의 `daangn-tone-references.csv`를 사용한다. `원문_유형`은 수집한 고객 메시지의 유형이며 새로 작성할 사내 공지의 목적과 같을 필요는 없다.
- 각 행의 `제목_질문`과 `원문_발췌`는 실제 원문이다. `내용_요약`, `톤_태그`, `참고할_표현_구조`, `이모지_관찰`은 AI가 작성한 분석이다. 원문 전체는 수록하지 않았다.
- 발췌는 HTML의 문단 구분을 줄바꿈으로 옮긴 텍스트다. 이미지·스크린샷의 문구, 서식과 이미지형 이모티콘은 포함하지 않는다. 포함 범위는 `원문_범위`에서 확인한다.
- `원문_기준일`은 공지의 게시일 또는 FAQ 페이지 데이터의 본문 수정일이다. `수집일`은 2026-10-03이다. 과거 자료의 서비스·정책 내용은 현재 사내 업무의 사실 근거로 사용하지 않는다.

## 말투와 구조

- 기본은 친근하고 정중한 해요체다. 설명은 쉽게, 행동 요청은 구체적으로 쓴다. 필요하면 공식적인 종결어미를 사용하되 한 공지 안에서 불필요하게 말투를 오가지 않는다.
- 일반 안내는 변경 이유와 영향을 먼저 설명한다. 일정·대상·신청 방법·문의 경로는 항목으로 구분한다. 조건과 예외는 해당 항목 가까이에 적는다.
- 참여 요청은 함께하는 분위기로 표현한다. 필수 여부와 마감 시각은 분명하게 밝히고, 미신청자를 질책하거나 죄책감을 유발하지 않는다.
- 불편이나 지연이 있는 상황은 영향을 인정하고 처리 방법을 안내한다. 확인되지 않은 원인이나 해결 시점을 단정하지 않는다.
- 짧은 FAQ처럼 답을 먼저 주고 절차를 뒤에 붙인다. 단계가 여러 개면 번호를 쓰고, 실제 버튼·메뉴 이름은 명확히 표시한다.

## 이모지

- 수집 자료에는 이모지가 없는 안내도 많다. 이모지 없는 원문에는 임의로 이모지를 추가하지 않는다.
- REF-008·013·025·030의 이모지는 감사·협조 요청을 부드럽게 마무리한다. REF-016의 편지 기호와 REF-021의 경고 기호는 문의·주의 사항을 표시한다. REF-029의 이모지는 기능 설명의 일부다.
- 사내 공지에는 기본적으로 이모지를 0~1개 사용하고, 밝은 행사 안내는 필요할 때만 더한다. 이는 프로젝트 작성 제안이며 당근의 공식 사용 기준은 아니다.
- 일정·마감·필수 행동은 텍스트만으로 이해되게 쓴다. 원문의 당근 이모지를 사내 공지에 자동으로 붙이지 않고 공지 주제와 조직의 표현 기준에 맞게 선택한다.

## 작성 순서

1. 현재 프로젝트의 목적·대상·일정·마감·필수 여부·신청 방법·문의 경로를 확인한다. 없는 사실은 만들지 않고 확인이 필요한 항목으로 남긴다.
2. 전달 방식이 비슷한 레퍼런스 2~3개를 고른다. 일정·변경 안내는 REF-002·008·010·011, 절차 안내는 REF-014·015·017·028, 참여·배려 표현은 REF-023·025·026을 참고할 수 있다.
3. 선택한 행의 표현 특징과 이 가이드를 적용해 새 문장을 작성한다. 고객 호칭·서비스명·규정·날짜·연락처는 복사하지 않고 현재 프로젝트 정보로 작성한다. 개인정보 방침의 문어체나 서비스 소개의 홍보성 표현은 필요한 상황에서만 참고한다.
4. 현재 공지의 정보와 행동 요청이 맞는지 검토한다. 초안 검토 기록에 참고한 레퍼런스 ID를 남기되 발송 본문에는 넣지 않는다.
