# 기획서에서 프로젝트 정보 채우기

2026년 10월 5일 화면 피드백을 반영한 구현 방향.

## 현재 프로토타입

등록 화면에서 `.txt`·`.md` 파일을 선택하거나 기획서 내용을 붙여넣을 수 있다. 항목 이름이 명시된 줄에서 프로젝트 제목·담당자·설명·신청 시작·마감 시각·행사일·신청 링크·확정 방식·종류의 **후보**를 찾는다. 후보마다 원문 근거를 보여주고, 운영자가 선택한 항목만 입력란에 채운다. 원문 전체는 저장하지 않고 적용한 값과 파일명만 로컬 저장한다. 시간이 없는 마감일이나 잘못된 날짜는 추측해 채우지 않는다.

이 기능은 규칙 기반 텍스트 추출이다. 문장형 PDF·Word 문서 해석, 여러 문서의 충돌 처리, AI 추출은 아직 없다. 직접 입력은 계속 가능하다.

## 다음 구현 순서

1. **파일 텍스트 추출:** PDF·DOCX·텍스트를 업로드하고 서버에서 형식별로 본문과 위치(페이지·문단)를 추출한다. 스캔 PDF는 OCR 결과임을 표시하고 신뢰할 수 없는 문자는 확인 대상으로 둔다. 파일 크기·형식 제한, 악성 파일 검사, 임시 파일 삭제를 적용한다.
2. **필드 후보 생성:** 먼저 날짜·URL·명시적 항목명을 규칙으로 찾는다. 문장형 설명과 모호한 항목에만 선택적 AI를 사용한다. 결과는 `{필드, 후보 값, 근거 원문, 문서 위치, 추출 방식}` 형태로 반환한다. 근거 없는 값은 비워둔다.
3. **충돌 검토:** 복수 문서에서 다른 마감일·대상·확정 방식이 나오면 자동으로 하나를 선택하지 않는다. 충돌값을 나란히 보여주고 운영자가 선택·수정한다. 이전에 직접 입력한 값도 덮어쓰기 전에 차이를 보여준다.
4. **확정·저장:** 운영자가 적용한 값만 프로젝트 운영 정보로 저장한다. 적용 시각과 출처를 남겨 이후 일정 변경과 초안 갱신을 추적한다. 링크 형식 검사는 가능하지만 실제 신청 권한과 정원 상태는 별도 확인이 필요하다.
5. **대상 명단:** 문서에 “마케팅팀 대상”처럼 범위가 쓰여 있으면 팀 선택 후보를 보여줄 수 있다. 실제 수신자 ID는 연결된 동료 명단과 대조해 운영자가 확정한다. 문서에서 사람 이름을 보고 동료 계정을 추측해 수신자로 확정하지 않는다.

실제 PDF·DOCX 업로드와 AI 처리는 서버 저장·접근 통제 범위 및 제공자에 전달할 자료 범위가 정해진 뒤 연결한다. 로컬 텍스트 후보 검토 화면은 이 단계의 사용자 흐름을 먼저 확인하기 위한 것이다.
